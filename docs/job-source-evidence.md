The metadata names the Ministry of Labour and Social Affairs as publisher and author, daily updates, "contains no copyright works", "database not protected by a sui generis right", and flags the dataset as containing personal data, so open availability does not lift data-minimization duties. Current `volna-mista.json.gz` is ~17 MB gzip / ~185 MB decoded, about 39,000 active vacancies, served with `Content-Encoding: gzip` so a standard `fetch` hands over decoded JSON. No per-vacancy detail URL exists; `urlAdresa` (employer page) is usually null. The incremental files (`volna-mista-prirustek-*`) share the schema plus a `typyZmenOpenData` code, but the matching code list (`typy-zmen-opendata`) is published empty and neither the schema nor the metadata states how a deletion appears or the replay order, so their semantics are unproven | Production full-snapshot-only adapter (`mpsv_cz`): the gzip/JSON stream is parsed record by record (one record in memory), then only the 5,000 most recently changed active, published, unexpired rows are retained (bounded min-heap ordered by `datumZmeny`, then `datumVlozeni`, then portal ID, so the result does not depend on file order); older rows beyond the cap are dropped and the source is marked `partial` with the count. A duplicate portal ID keeps the version with the later `datumZmeny`. Each row keeps its own identity (`mpsv_cz:<portalId>`), so same-title rows, undisclosed-employer rows and rows sharing an employer URL are never merged. A snapshot whose `Last-Modified` is older than 7 days imports nothing and is reported as a failed (stale) source. The raw-gzip fallback path cannot apply backpressure because the HTTP client's chunk callback is synchronous; its memory is bounded by the 1 GiB compressed transfer cap, the decoded-size cap and the per-record cap (normally `fetch` already hands over decoded JSON). Increments are not used; each run is a complete replacement, so a vacancy removed upstream, past `expirace` (Prague date), or not marked for publication (`zverejnovat` other than `ano`/`anoeu`/`anosp`) is absent from the next run. Code lists (`obce`, `okresy`, `kraje`, work relationship, shift, education, skills, languages) are fetched from the official `/od/soubory/ciselniky/` directory; unknown codes stay unmapped. Salary is CZK per month or per hour from `typMzdy`; the link is the employer URL when valid, otherwise the official dataset page with a record fragment. Attribution: Czech Ministry of Labour and Social Affairs / Labour Office of the Czech Republic. **Retention and personal data:** the contact-person block (`prvniKontaktSeZamestnavatelem`: name, titles, position, e-mail, phone) and `pracoviste[].email/telefon` are never read, stored, logged, reported or placed in fixtures (whitelist mapping, fixed error messages, fixture scan test).
